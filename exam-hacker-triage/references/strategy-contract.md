# Planning in Markdown

The canonical current plan is `progress/progress.md`. Follow the shared learning record in the installed/sibling `exam-hacker` skill. No separate outline mirror or JSON state is generated.

Include:
- the goal, known exam facts, confirmed time and relevant uncertainty;
- capability-level mastery conclusions with evidence links;
- prioritized findings and their repair/pass conditions;
- one current task or a clear statement that a task has not yet been presented;
- one immediate action, plus short conditional next steps when useful.

Estimate work against remaining confirmed capacity; do not count completed work as future time. Record study time only when observed/reported, not from elapsed chat time. Distinguish “exam elapsed date” from “study minutes used”.

A block groups related capabilities and reproducible methods. It can contain several short practice/explanation tasks; it is not permission to produce every chapter summary at once.

The exam date is absolute and timezone-qualified. Store no stale countdown as a fact. Explain target feasibility conditionally when evidence or ability is unknown.

When replanning, preserve prior observations, completed work, and source identities. Changes to exam facts require new factual evidence, not a bad quiz result. A completed task with failed criteria remains failed and may require another task.

The first decision must lead to an actual learner action unless the user requested only the plan or a critical input is missing.
