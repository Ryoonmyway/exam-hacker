# Exam Hacker Replan

Change only decisions that the new facts justify.

Read the shared `exam-hacker/references/learning-record.md` and `continuation.md`, then [decision updates](references/loop-state-contract.md). Recover current progress, relevant new observations and explicit constraint changes; do not load all history.

## Establish what changed

Raw answers belong to drill for grading first. A user's external grade or self-report may be recorded as such without pretending to have inspected the work. An explanation request or “understood” may need only local support and a short verification, not a new course plan.

If neither evidence nor constraints nor a corrected prior decision changes the next action, do not rewrite the plan. Continue the existing task.

New source material is audited by triage before exam facts change. Triage can add source entries to an existing course without resetting it; return here for resulting priority changes.

## Recalculate

Compare goal relevance, the demonstrated gap, feasibility and remaining confirmed time. Do not treat new poor performance as evidence of different exam weights.

Preserve historical observations and completed work. Resolve conflicting evidence by relevance, recency and conditions; lower confidence when needed. A correction is traceable, not an overwritten past.

Review P0/P1/P2 findings, repair/pass conditions, deferred topics and abandonment risk. Retain only a small useful look-ahead. Time already spent is not future demand; wall-clock silence does not prove study time.

Write the changed decisions in `progress/progress.md` with a dated reason and evidence links. There is no mandatory version increment or JSON evidence cursor. Save any newly reported observation in its relevant practice/history record before relying on it.

## Execute the next move

Choose the next concrete objective. Use compress if a method gap needs explanation, otherwise drill to present the task. Stay in the same turn until an actual learner action is ready.

Do not replace a pending task unless the new decision makes it inappropriate. If it is replaced, retain its unfinished status and reason in the record.

Report only material changes, including time tradeoffs or revised confidence. Follow the continuation rules; do not hand a Session ID back to the user as the whole next step.
