# Feedback and current state

Use the shared Markdown learning record; this reference describes grading decisions, not a separate state format.

Before grading, inspect the task, previous attempts, answer exposure, and relevant source logic. If necessary render and visually inspect the exact source/answer pages. Failed text extraction alone is not missing evidence.

Record:
- observed work and conditions;
- correct/incorrect/uncertain elements and their grading basis;
- a provisional diagnosis where interpretation is needed;
- the capability actually demonstrated;
- immediate repair or progression and its pass criterion.

Do not mistake arithmetic slips, misunderstood wording, fatigue reports, or a defective question for a proven conceptual gap. When explanations compete and would change instruction, use a short targeted probe.

Diagnosis is actionable: P0 blocks the present goal, P1 is a consequential current loss, P2 can wait. Combine the gap with goal relevance, prerequisites, evidence and available time; do not derive priority from a numerical ability level alone.

Append attempt/correction records with stable IDs. A correction points to the earlier observation; it does not erase it. Preserve contradictions and resolve them using relevant, recent, appropriately conditioned evidence. If unresolved, reduce confidence.

A self-report updates the reported state immediately, but does not become independent performance. Showing an answer changes the assessment conditions; later verification requires a fresh task.

Update the entry after saving the observation. If a consequential plan change is needed, use replan in the same turn. Local support changes need no global replan. Record no fictional revision or capacity consumption merely to make a receipt look complete.
