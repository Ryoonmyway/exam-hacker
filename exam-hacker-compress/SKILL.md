# Exam Hacker Compress

Create one useful Markdown explanation, then connect it to application.

Read the shared `exam-hacker/references/learning-record.md` and `continuation.md`, plus [artifact guidance](references/artifact-contract.md). Recover the requested block, current task and source basis; avoid rereading unrelated course history.

## Pick the learning unit

A block can contain several connected methods. Identify the next checkable endpoint needed now; cover the smallest coherent chain that reaches it. Do not compress an entire course merely because its chapter names are available.

Use local repair when the user's report OR observed work pinpoints a gap. State the observation behind that choice; do not treat a weak broad mastery label as proof of a specific misconception. If the failure is ambiguous and changes what to explain, use a small discriminating task.

If the learner already demonstrates this chain, skip redundant notes and use drill for transfer. If they explicitly want review anyway, provide it.

## Build the explanation

Preserve:
- cue and applicability conditions;
- necessary concepts, inputs and sign conventions;
- ordered operations and why each is justified;
- intermediate checks and a verifiable endpoint;
- relevant failure boundaries and intentionally omitted detail.

Follow real source anchors. For sparse/scanned PDFs, inspect the relevant rendered pages before relying on formulas or diagrams. If source basis or essential endpoint is unknown, recover it or ask for that specific input. General teaching must be labeled as such, not attributed to the course.

Write or update `progress/notes/<block>.md`, linking to existing material instead of duplicating it. Do not generate a JSON counterpart, a catalog of every internal node, or a separate artifact-binding revision protocol.

## Continue

The note does not demonstrate mastery. Record what was explained and the pending next action without upgrading ability.

Unless the user requested explanation only, use drill in the same turn to present one answer-hidden retrieval/application task. Derive the prompt from the intended capability, verify it, and save it in the practice record rather than duplicating it inside the note. Respect a pending task: if explanation revealed its answer, mark that exposure and use a fresh variant for independent verification.
